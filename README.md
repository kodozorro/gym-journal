# Журнал тренировок

Приложение для телефона: быстро записывать тренировки в зале и смотреть прогресс.
Данные хранятся в личной Google Таблице владельца. Приложение берёт из неё план и пишет в неё
вес, повторы, километры и минуты.

- Приложение: <https://kodozorro.github.io/gym-journal/>
- Как поставить скрипт в таблицу и приложение на телефон: [docs/setup.md](docs/setup.md)

## Что умеет

- **Сегодня.** Тренировка дня из таблицы: упражнения парами, план, тренажёр и запись с прошлого
  раза. Повторы записываются одним касанием, вес меняется кнопками «−» и «+».
- **Справка.** У каждого упражнения есть кнопка «i»: фото тренажёра, рисунок двух крайних
  положений, какие мышцы работают и как делать. Открывается и без сети.
- **Отдых.** Таймер запускается сам, когда записан круг пары, и считает по часам телефона.
- **План.** Все недели программы. Любой день можно открыть и записать позже.
- **Прогресс.** Километры и тренировки за неделю, лучший вес по упражнению, ходьба по неделям.
- **Без сети.** Приложение открывается из памяти телефона, записи ждут в очереди и уходят в
  таблицу, когда связь появится.

## Как устроено

```
телефон (PWA) ── POST, JSON, ключ в теле ──► Apps Script в таблице ──► лист «Журнал»
```

- Статический сайт без сборки и без зависимостей: `index.html`, `css/`, `js/`, `sw.js`.
- Мостик к таблице — скрипт Apps Script, привязанный к ней: [`apps-script/Code.gs`](apps-script/Code.gs).
  Он пишет только в ячейки ввода листа «Журнал» (столбцы E–J и L) и ничего не знает о
  других файлах владельца.
- Адрес скрипта и ключ вводятся в приложении и хранятся только на телефоне. В репозитории нет
  ни ключа, ни адреса, ни ссылки на таблицу: за этим следит тест `tests/repo.test.mjs`.
- План тренировок живёт в таблице, а не в коде. В коде есть только справочник
  (`js/core/guide.js`): по названию тренажёра из таблицы он находит фото, рисунок и подсказки.
  Тренажёр узнаётся по типу, без марки: «… Seated Leg Press» любой фирмы — жим ногами сидя.

| Папка | Что в ней |
|---|---|
| `js/core/` | Логика без браузера: даты, разбор плана, журнал, очередь записей, таймер, шкалы графиков |
| `js/data/` | Хранилище на телефоне, обращения к скрипту, синхронизация |
| `js/ui/` | Экраны, нижние листы и рисунки упражнений (`art.js`) |
| `js/platform/` | Звук, вибрация, удержание экрана, установка и обновление |
| `img/machines/` | Фото тренажёров для справки: WebP 800 × 600 на белом фоне |
| `apps-script/` | Скрипт для таблицы |
| `tools/` | Сервер для разработки, учебная таблица в памяти, штамп версии, значки |
| `tests/` | Тесты логики, скрипта и сценарии в браузере |

## Разработка

Нужен Node.js 20 или новее. Зависимостей нет, `npm install` не требуется.

```bash
npm run dev        # приложение на http://127.0.0.1:8080/gym-journal/ и учебный мостик
npm test           # тесты логики, скрипта и репозитория
npm run test:e2e   # сценарии в браузере (нужен Playwright с Chromium)
npm run check      # всё вместе, как перед слиянием
npm run stamp      # обновить версию после правки файлов приложения
```

`npm run dev` поднимает настоящий `Code.gs` поверх учебной таблицы в памяти с выдуманными
числами. Адрес и ключ для экрана настроек он печатает в консоль. С настоящей таблицей и Google
ни сервер, ни тесты не связываются.

Версия приложения записана в `sw.js` и `js/version.js`. Она считается по содержимому файлов,
поэтому после любой правки приложения нужен `npm run stamp`: иначе телефоны не узнают об
обновлении, а тест напомнит об этом.

Снимки экранов на учебных данных: `node tests/e2e/screenshots.mjs папка`.

Рисунки упражнений собраны из линий прямо в коде и перекрашиваются под тему. Фото тренажёров
в `img/machines/` — снимки из каталога оборудования; права на них принадлежат их владельцам.

## Публикация

GitHub Pages отдаёт ветку `main` из корня репозитория. После слияния сайт обновляется сам, а
приложение на телефоне предлагает обновиться при следующем открытии.

Если менялся `apps-script/Code.gs`, владельцу нужно вставить новый код в редактор скрипта и
выпустить новую версию развёртывания: [docs/setup.md](docs/setup.md#обновить-скрипт-после-изменения-кода).

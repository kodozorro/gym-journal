# Журнал тренировок: правила репозитория

Личное приложение одного человека: записывать тренировки с iPhone в его Google Таблицу и
смотреть прогресс. Репозиторий публичный, сайт отдаёт GitHub Pages из ветки `main`.
Полное описание проекта и таблицы лежит в файлах проекта, а не здесь: в нём есть личные данные,
в репозиторий его не копировать.

## Правила владельца

- Репозиторий публичный. Не коммитьте личные данные о здоровье, секретный ключ скрипта
  Apps Script, адрес его веб-приложения и ID таблицы. То же относится к описаниям pull request,
  задачам, тестовым данным и снимкам экрана: в них только выдуманные числа.
- Таблица — единственное хранилище данных. Приложение и скрипт пишут только в ячейки ввода
  листа «Журнал» (столбцы E–J и L). Формулы, графики и структуру листов без согласия владельца
  не менять.
- План тренировок берётся из таблицы, а не из кода. Менять программу можно только с опорой на
  опубликованные исследования или рекомендации, с указанием источника.
- Одна ветка и один pull request на задачу. Перед тем как назвать работу готовой, прогоните
  автотесты и откройте приложение в браузере на ширине 390 px в светлой и тёмной теме. Итог
  тестов и снимки экрана приложите к последнему сообщению.
- Коммиты только от имени владельца. В сообщениях коммитов нет строк о соавторах и ссылок на
  сеанс. Названия моделей не упоминаются нигде в репозитории.
- Pull request в `main` сливает поток сам, сразу после зелёных проверок: так решил владелец.
  Включать GitHub Pages, менять таблицу и просить владельца заново развернуть скрипт можно
  только после его «да».
- Если чего-то не хватает (доступа, коннектора, сети, ответа на вопрос), скажите об этом сразу
  и остановитесь. Не подменяйте и не угадывайте.
- Отвечайте владельцу по-русски и коротко: сначала результат, затем что нужно от него.

## Что решено

- Телефон владельца — iPhone. Приложение ставится из Safari на экран «Домой». Вибрации и
  фоновой отправки там нет: таймер подаёт звук, а очередь уходит, пока приложение открыто.
- Экран замеров не нужен. Листа «Замеры» в таблице нет, приложение и скрипт его не создают.
- «Сегодня» считается по часам телефона. Часовой пояс таблицы приложение не трогает.
- Шаг веса настраивается в приложении отдельно для каждого упражнения.
- У каждого упражнения есть кнопка «i»: фото тренажёра, рисунок и техника. Фото взяты из
  каталога оборудования зала, владелец разрешил положить их в репозиторий. Название зала, его
  адрес и сайт в репозиторий не попадают, марки тренажёров в код и названия файлов тоже.
- Сборки и зависимостей нет: обычные модули JavaScript, тесты на `node --test`.
- Кроме сайта есть приложения на Swift для iPhone и Apple Watch (`ios/`). Сайт остаётся: все
  работают с одной таблицей через один и тот же скрипт. Экраны iPhone повторяют сайт, на часах —
  быстрая запись подходов и веса.
- В таблицу пишет только телефон. Часы обмениваются с ним; адреса скрипта и ключа у них нет.
- Тренировку в «Здоровье» начинают кнопкой: силовую в день с тренажёрами, ходьбу в день с
  ходьбой. Ведут её часы, телефон открывает приложение на них сам. Без часов телефон записывает
  только вид тренировки и её время. Иначе, чем началом тренировки, телефон приложение на часах
  не открывает: у iOS такого способа нет.
- Отрезок ходьбы, записанный вручную на телефоне или часах, телефон сохраняет в «Здоровье» как
  ходьбу: на его минуты и километры. Шаги, пульс и калории приложение не пишет: это были бы
  выдуманные числа.
- Ходьба идёт частями, до и после силовой: кнопка «Ходьба» остаётся, пока километров записано
  меньше, чем в плане.
- Конец отдыха в приложениях на Swift: звук и вибрация на iPhone, вибрация на часах. Каждый
  сигнал выключается в настройках.

## Команды

Нужен Node.js 20 или новее, `npm install` не требуется.

```bash
npm run dev        # приложение и учебный мостик на http://127.0.0.1:8080/gym-journal/
npm test           # логика, скрипт, репозиторий
npm run test:e2e   # сценарии в браузере, нужен Playwright с Chromium
npm run check      # штамп версии и все тесты: запускать перед слиянием
npm run stamp      # обновить версию после правки файлов приложения
node tests/e2e/screenshots.mjs папка   # снимки 390 px в двух темах и сводные листы
npm run ios:data   # данные для приложений на Swift из кода сайта
```

Приложения на Swift собираются только на Mac с Xcode и XcodeGen:

```bash
cd ios/Core && swift test          # общая логика, сверяется с сайтом по эталонам
cd ios && xcodegen generate        # проект Xcode из project.yml, в репозиторий он не попадает
xcodebuild -project GymJournal.xcodeproj -scheme GymJournal -destination 'generic/platform=iOS Simulator' build
xcodebuild -project GymJournal.xcodeproj -scheme GymJournalWatch -destination 'generic/platform=watchOS Simulator' build
```

Если тест упал, перезапускайте только его: `node --test --test-name-pattern "часть названия" файл`.
Весь набор — один раз в конце.

## Как устроено

```
телефон (PWA) ── POST, JSON, ключ в теле ──► Apps Script в таблице ──► лист «Журнал»
```

- `js/core/` — логика без браузера: даты, разбор журнала и плана, очередь записей, таймер.
- `js/core/guide.js` — справочник для кнопки «i». По названию тренажёра из таблицы находит его
  тип (общие слова вроде «seated leg press», без марки), по типу и названию упражнения — фото,
  рисунок и подсказки. Программу он не задаёт: подходы, повторы и вес берутся из таблицы.
- `js/data/` — хранилище на телефоне, обращения к скрипту, синхронизация.
- `js/ui/` — экраны на маленьком собственном виртуальном DOM (`vdom.js`), нижние листы на
  `<dialog>`, своя цифровая клавиатура.
- `js/ui/art.js` — рисунки упражнений из линий: два крайних положения и стрелка усилия.
  `img/machines/` — фото тренажёров, WebP 800 × 600 на белом фоне.
- `js/platform/` — звук, вибрация там, где она есть, удержание экрана, установка и обновление.
- `sw.js` — кэш с версией в имени. Новая версия не включается сама посреди тренировки: приложение
  показывает полосу «Вышла новая версия».
- `apps-script/Code.gs` — мостик. Действия `pull`, `push`, `ping`. Ключ сверяется раньше любого
  обращения к таблице. Перед записью скрипт сверяет заголовки листа «Журнал».
- `tools/gas-fake.mjs` и `tools/fixture.mjs` — учебная таблица в памяти с выдуманными числами.
  На ней настоящий `Code.gs` работает в тестах и в `npm run dev`.
- `tests/e2e/harness.mjs` — запросы страницы к `script.google.com` перехватываются и уходят в
  `Code.gs` поверх учебной таблицы. С настоящей таблицей и Google тесты не связываются.

Приложения на Swift (подробно — в `ios/README.md`):

- `ios/Core/` — пакет `GymJournalCore`: перенос `js/core` и `js/data` на Swift без интерфейса,
  общий для телефона и часов. `WatchLink.swift` — обмен телефона и часов. `WalkLog.swift` —
  ходьба для «Здоровья» по отрезку, записанному вручную.
- `ios/App/` — приложение для iPhone на SwiftUI. `ios/Watch/` — приложение для часов.
- `ios/tools/generate.mjs` — делает из кода сайта рисунки, значки, учебный журнал и эталоны, по
  которым тесты Swift сверяют перенос логики.
- Оба приложения запускаются с учебным журналом: параметры `-demo YES -demoToday … -demoScene …`.
  Так делаются снимки экрана в симуляторе, без таблицы и «Здоровья».

Лист «Журнал»: строка 2 — заголовки, одна строка — одно упражнение одного дня. Столбцы A–D, K и
M (дата, тренировка, упражнение, план, тренажёр, неделя) таблица заполняет сама по листу
«Программа». Приложение их только читает. Строка ищется по дате и названию упражнения, поэтому
название должно совпадать в «Журнале», «Программе» и на листе «Прогресс».

## О чём легко забыть

- После любой правки файлов приложения нужен `npm run stamp`. Иначе телефоны не узнают об
  обновлении, а `tests/repo.test.mjs` упадёт.
- В кэш для работы без сети попадают страница, манифест и папки `css`, `js`, `icons`, `img`:
  список собирает `tools/stamp.mjs`. Файл приложения вне этих папок нужно добавить туда же. Тест
  проверяет, что всё, что загружает страница, в кэше есть.
- Новый тренажёр или упражнение в таблице нужно добавить в `js/core/guide.js`, иначе кнопка «i»
  покажет только ссылку на поиск фото. Нужны тип тренажёра, фото в `img/machines/` и рисунок в
  `js/ui/art.js`. Подсказки о технике — общепринятые правила работы на тренажёре; правила
  программы в них повторяются только те, что уже есть у владельца. `tests/guide.test.mjs`
  сверяет справочник с папкой фото, рисунками и учебной программой.
- Цвет в рисунках задаётся только классами `art__…` из `css/app.css`, а толщина линий — в коде:
  так рисунок перекрашивается под тему. В подписи к рисунку фигура «яркая», а не «тёмная»: в
  тёмной теме она светлая.
- Сайт живёт в папке `/gym-journal/`, поэтому все пути в манифесте, странице и сервис-воркере
  относительные.
- Политика безопасности страницы задана в `index.html`. Встроенных скриптов и стилей,
  `innerHTML` и `eval` в приложении нет: это тоже проверяет тест.
- Класс, использованный в `js/ui/`, должен быть описан в `css/app.css`. Пары цветов текста и
  фона проверяются на контраст в обеих темах.
- После правки `apps-script/Code.gs` владельцу нужно выпустить новую версию развёртывания
  (см. `docs/setup.md`). Просить об этом можно только с его согласия. Если меняется формат
  обмена, поднимайте `API_VERSION` в скрипте и в приложении вместе.
- Логика есть в двух местах: `js/core` и `ios/Core`. Меняйте её сначала на сайте, затем в
  Swift, и запускайте `npm run ios:data`: эталоны обновятся, и `swift test` покажет, где перенос
  разошёлся с сайтом. То же после правки `js/ui/art.js`, `js/ui/icons.js`, `apps-script/Code.gs`
  и `tools/fixture.mjs`. Если данные отстали от кода, упадёт `tests/ios.test.mjs`.
- Цвета приложений на Swift повторяют `css/app.css`: iPhone — обе темы, часы — тёмную. Тест
  сверяет их с таблицей стилей.
- Код на Swift нельзя назвать готовым без Mac: нужны `swift test`, сборка обеих схем и показ с
  учебными данными в симуляторах iPhone и часов.
- Проект Xcode и `ios/Config/Local.xcconfig` с командой разработчика в репозиторий не попадают.
- Часы с watchOS 27 подключаются к Mac только из Xcode 27 (Device Hub, «Pair Nearby Device…»),
  а ему нужна macOS 26.6 или новее: см. `docs/ios.md`. Проект собирается в Xcode 26.6 и 27.1.
  На настоящие iPhone и часы приложения ставятся из Xcode с бесплатной подписью, она живёт
  7 дней. Первый запуск на часах ждёт, пока Xcode скачает отладочные символы watchOS, около
  3,5 ГБ.
- Запись в «Здоровье» и обмен телефона с настоящими часами в симуляторе до конца не проверить:
  подпись и запуск на устройствах делает владелец в Xcode. Правку, которая их касается,
  называйте проверенной только в той части, которую видели сами.
- Учебные адрес и ключ для тестов перечислены в `tests/repo.test.mjs`. Любая другая строка,
  похожая на ключ, адрес скрипта или ID таблицы, остановит тесты.
